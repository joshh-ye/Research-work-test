# Priority D design: E4 supervised baseline (SD-008), E5 seed/fold sensitivity (SD-009), E8 generalisation (SD-012)
Written 2026-10-20 before any long job. hg38 throughout. Code: `analysis/priorityD/`; outputs `results_phase2/{trunk_cache,e4_ridge,e5_seeds,e5_folds,e8_generalisation}/`; commands in `RUNS.md`.

## 1. What the code says (main.py, borzoi_code/model.py, dataset.py)
- Borzoi-TL = 4 frozen `johahi/borzoi-replicate-{0..3}` trunks; embedding tapped as the INPUT of `human_head` (1920 ch x 6144 bins x 32 bp), mean over replicates, central 4096 bins -> head Linear(1920,1024)-GELU-Dropout(.2)-Linear(1024,183)-Softplus, applied per 32 bp bin.
- Training (slurm 12212537, defaults of main.py): batch = 1 tile, Adam lr 1e-4, wd 1e-4, Poisson NLL (`log_input=False`, mean over bins x tracks), ReduceLROnPlateau(.5, patience 1), 8 epochs, early stop patience 3 on val loss, best ckpt on val loss (epoch 5), aug = random whole-bin shift in [-4,4] bins (+-128 bp) of the 524,288 bp window + RC p=.5; no seed set. Val chr1+chr8 (750 tiles), test chr9+chr22 (359), train 4,659 (all other chromosomes incl. chrX).
- Cost of the original: 6.6 h/epoch (trunk dominated, 1.57 s/tile). The pretrained-Borzoi re-run measured 0.70 s/tile GPU for the 4-replicate forward (253 GPU-s / 359 tiles; Qing `run_info_test.json`). Original head training is therefore ~52 h of trunk compute; cannot be repeated per seed/fold.
- Shared evaluation grid ("shared128"): crop 256 bins/side of the central 4096, mean-pool x4 -> 896 x 128 bp, applied identically to predictions and targets (`enformer_baseline_utils.targets_to_enformer_grid`). All metrics below use it; per-tile sufficient statistics in the same format as `reports/qing_deliverables/.../tl_per_tile_sufficient_stats_shared128.npz`, so `analysis/exposure_stratified/estats.py` is reused for r / r^2 / prediction R^2 and tile-block bootstraps.

## 2. Trunk-embedding cache (E5 enabler) - FEASIBLE
One GPU pass, per tile (524,288 bp), saved as per-tile .npy (atomic, resumable): fwd embedding (4104 x 1920 fp16 = central 4096 + 4 margin bins/side), RC embedding (same, from the RC window), pretrained 4-replicate human-head outputs for all 7,611 tracks pooled to shared128 (896 x 7611 fp16), and BigWig targets (4104 x 183 fp32) for the same window. Pretrained outputs come out of the same forward (no second pass), so E4 needs no extra inference.
- Estimates (unshared A100): ~1.4 s/tile (fwd 0.7 s + RC 0.6 s) x 5,768 tiles = **~2.3 GPU-h**; disk 48 MB/tile -> **~278 GB** (emb_fwd 91 GB, emb_rc 91 GB, pre128 78 GB, tgt 17 GB); panfs shows 1.9 PB free (no user quota visible). RC embeddings are cached for ALL tiles because other chromosome folds train on chr1/8/9/22 tiles.
- Targets: `bw_bin_means` (BigWig `intervals()` -> mean over covered bases per 32 bp bin) replaces `pyBigWig.stats(nBins)` (41 s/tile measured, would have taken ~9 h); verified equal to the original loader to rel. 1e-5 on dense/sparse train tiles (`tests/test_cache.py`) and identical to `results_full/test_targets.npy`.
- DEVIATIONS from the original recipe (all documented, none uses test data): (a) shift augmentation is emulated by re-slicing the cached embedding of the UNSHIFTED window (context shifts <=128 bp are ignored; the original recomputed the trunk); (b) RC is the real RC forward (not a flip); (c) fp16 storage (rel. err ~5e-4). Gate: original checkpoint on the cache must reproduce test mean r 0.6820 and `results_full/test_preds.npy` (tests: 4 real test tiles correlate >0.999 with stored predictions).
- Any head retrained on the cache is therefore "cache-emulated original recipe"; the headline TL number remains the original checkpoint. E5 compares cache-retrained seeds with the cache-evaluated original checkpoint and with pretrained Borzoi.

## 3. E4 supervised baseline (SD-008) - ridge / linear probe
- X = pretrained 4-replicate Borzoi outputs on shared128 (all 7,611 human tracks = primary, pre-specified; variants: 1,882 ChIP-TF eligible, 132 CRC list `variant_scoring/track_lists/borzoi_pretrained_crc_tracks.tsv`; raw or log1p features), Y = 183 raw targets on shared128. Also a linear probe on the 1,920-d trunk embedding at 32 bp (pooled predictions evaluated on shared128).
- Same training chromosomes as TL (4,659 tiles x 896 grid bins = 4.2 M rows). Streaming float64 Gram X'X, X'Y on the GPU (463 MB for p = 7,611), standardised features + intercept, eigendecomposition once, lambda grid {1e-6..1e2} (correlation-matrix scale) chosen ONLY on validation chromosomes (mean per-track Pearson r); test tiles never enter fit or selection (unit-tested). Grid-edge optima are flagged.
- Pre-specified comparison: TL vs ridge(all7611, raw) and vs best-on-validation variant; pretrained non-oracle validation-selected single-track mapping (04_pretrained_valsel.py; gate: orig fold must give mean r 0.6609 as in `analysis/exposure_stratified`). Pearson r primary; r^2 and prediction R^2 reported separately; ridge/TL R^2 raw, pretrained valsel R^2 validation-calibrated (labelled).
- Cost: Gram pass ~10 min per feature set (I/O bound 63 GB; GPU fp64 minutes); no new inference.

## 4. E5 sensitivity (SD-009)
- Head seeds 1-3 (primary) + 4-5 (extras), orig split, identical hyperparameters, explicit seed (init, dropout via torch seed; epoch order/shift/RC from seed+epoch RNG, resumable per epoch). Head training on cache ~10-25 min each (I/O of 88 GB/epoch served by page cache after epoch 1).
- Chromosome folds (folds.py; disjoint test sets): orig (val chr1,8; test chr9,22), F2 (val chr3; test chr6,21), F3 (val chr4; test chr11,19,20), F4 (val chr5; test chr7,18); remaining chromosomes train. Per fold: TL head (seed 1; seeds 2-3 as extras), ridge(all7611), pretrained valsel (selected on the fold's own validation chromosomes). Report spread of mean r and delta r vs pretrained, tile-block bootstrap CIs per fold; no pooled p-values. SD-009 clarification: folds test head robustness only, backbone exposure unchanged.
- No-RC ablation (seeds 1-3, `--no-rc`): lowest priority, runs last.

## 5. E8 held-out-vocabulary generalisation (SD-012) - labelled "validation-selected same-TF transfer"
Head retrained without the 17 tracks of GP5d (68-73), LS174T (98-102), LS180 (118-122), DLD-1 (10) (exposure_audit: no cell-line exposure in Borzoi/Enformer vocabularies). Each held-out track is predicted by one trained TL output chosen with a pre-fixed rule on validation chromosomes only: same-TF trained track (all in other cell lines; exists for CTCF, HNF4A, NIPBL, RAD21, SMC3, GATA6, CEBPB, CDX2 = 13 tracks) with max val r; fallback (REPIN1, VDR, ZBTB17 x2 = 4 tracks) = max-val-r over all 166 TL outputs. Compared on the same tiles/grid with pretrained Borzoi non-oracle val-selected mapping, plus the original (leaky) TL head as an upper reference. Enformer comparator not included (no Enformer outputs in the cache; E7 covers it). Only 4 cell-line clusters exist: cluster table + sign-flip p are descriptive (min attainable p 0.125); tile-block CI ignores track/cell-line variance. Seed 1 (extras: seeds 2-3 if time).

## 6. Schedule and resources
GPU is shared with Borzoi (PID 3442888, ~6 h) and Enformer (PID 3444921, ~2-3 h) scoring jobs: `queue_cache.sh` waits for BOTH PIDs, then builds the cache; `queue_downstream.sh` waits for `CACHE_COMPLETE` then runs E4 > E5 seeds > E8 > E5 folds > extras in that order, each step skipped if output exists and skipped if < 40 min of the Slurm allocation (job 14717985) remain. Estimated GPU after the scoring jobs end: cache ~2.3 h + E4 ~1 h + 13-20 head trainings ~4-6 h = ~8-9 h; the allocation had 21.8 h left at design time (~6 h waiting + ~9 h = ~15 h; slack ~6 h). If the allocation is short, the extras (seeds 4-5, fold seeds 2-3, no-RC) are dropped first.
Risks: panfs read throughput for head epochs; 05_e8.py and the cache-dependent parts of 06 could only be unit-tested on synthetic/partial data (3 real cached tiles + fixtures), so first real run may need a fix.
